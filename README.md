# ПУХ — Пассивный Учёт Хвостатых

Мини-приложение «Ферма невидимых кроликов»: детектор, который по косвенным сигналам
(пропала морковка, новая ямка, датчик движения, шуршание, следы) оценивает, сколько
невидимых кроликов на ферме, насколько система уверена в оценке, какие сигналы
повлияли сильнее всего — и выдаёт фермеру рекомендации. Любое изменение данных или
параметров пересчитывает всё мгновенно.

## Сценарий и почему он выбран

Кроликов увидеть нельзя — можно только оценивать их по косвенным уликам. Это делает
задачу честной витриной для интерактивной аналитики:

- **Неопределённость показана буквально** — диапазон «3–6» и призрачные кролики
  (залитые силуэты — подтверждённый минимум, контурные — возможные сверх него).
- **Объяснимость** — каждый бар вклада раскладывается в подстановку формулы,
  панель «Как это посчитано» показывает расчёт на текущих числах.
- **Deadpan-тон**: серьёзный оперативный терминал про абсурдный объект — юмор
  рождается из контраста, а не из шуток в данных.

## Стек

- Vite + React 18 + TypeScript (strict)
- Чистый CSS с дизайн-токенами (без UI-китов и Tailwind)
- Собственные SVG: глифы сигналов, карта фермы, gauge, бары — без chart-библиотек
- Состояние: `useState` + чистые функции модели; вся математика — в `src/model/`
- Тесты: Vitest (`src/model/engine.test.ts`)
- Шрифты Unbounded и Inter самохостятся в `public/fonts` — в рантайме нет обращений к CDN

## Как работает модель

Вся математика — чистые функции в `src/model/engine.ts` (UI их только вызывает).

**1. Вклад события**

```
contribution = count × rabbitsPerUnit × reliability × intensityFactor × decay
intensityFactor = 0.6 + 0.08 × intensity        // интенсивность 5 → ×1.0
decay = 0.5 ^ (ageHours / halfLife)             // свежие сигналы важнее
```

«Сейчас» модели — время самого позднего включённого события; `halfLife`
(по умолчанию 6 ч) настраивается в «Штабе».

**2. Оценка по зоне**

```
locEstimate = Σ contributions / √(число событий в зоне)
```

Поправка `√n` — против двойного счёта: несколько сигналов в одной зоне частично
описывают одних и тех же кроликов.

**3. Итог и диапазон**

```
total = Σ locEstimate
диапазон = [total × confidence … total × (2 − confidence)]
```

По центру — округлённый `total`; чем ниже уверенность, тем шире вилка.

**4. Уверенность (0..1 → %, округление до 5%)**

```
confidence = 0.35 × надёжность (средняя, взвешенная по вкладу)
           + 0.25 × разнообразие (уникальные типы / 5)
           + 0.20 × свежесть (средний decay)
           + 0.20 × подтверждённость (доля зон с ≥2 сигналами)
```

**5. Уровень угрозы** — по центру диапазона: `< 2` — «Спокойно», `2–6` —
«Повышенная активность», `> 6` — «Нашествие». Пороги настраиваются.

**Крайние случаи**: 0 включённых событий → оценка 0, уверенность 0%, дружелюбный
empty state; NaN и делений на ноль нет (покрыто тестами).

### Коэффициенты типов сигналов

| Тип | Надёжность | Кроликов/ед. | Почему |
|---|---|---|---|
| Датчик движения | 0.90 | 1.0 | Электроника почти не врёт: одно срабатывание — один конкретный кролик |
| Новая ямка | 0.75 | 0.8 | Почти наверняка кролик, но один кролик может вырыть несколько ямок |
| Следы | 0.70 | 0.5 | Много отпечатков оставляет один и тот же кролик |
| Шуршание | 0.60 | 0.7 | Шуршит и ветер, и мыши — доверяем осторожно |
| Пропала морковка | 0.55 | 0.4 | 5 морковок мог съесть один прожорливый кролик |

Надёжность каждого типа можно переопределить в «Штаб → Продвинутые».

### Рекомендации

Rule-based, у каждой — приоритет и причина: наблюдение в самой «населённой» зоне,
датчик в зону только со слабыми сигналами, проверка забора при ямках, защита
моркови при массовых пропажах, запрос данных при уверенности < 50%.

## «Отчёт смены»: как встроен ИИ

LLM вынесен на периферию и **ничего не считает** — вся математика остаётся в
детерминированных функциях `src/model/`. Кнопка «Сформировать отчёт» отправляет
уже посчитанные факты (диапазон, уверенность, эпицентр, топ-сигналы, действия)
в serverless-функцию [`api/summary.ts`](api/summary.ts), а та — в LLM, который
пересказывает цифры человеческим рапортом.

Принципы безопасности:

- ключ живёт только в env на сервере (`AI_API_KEY`), в браузер не попадает;
- публичный эндпоинт защищён лимитом запросов по IP и малым `max_tokens`;
- при любой ошибке (нет ключа, сеть, лимит) клиент молча собирает отчёт
  локальным шаблоном (`src/model/report.ts`) — фича работает всегда.

Включение на Vercel: Settings → Environment Variables →

```
AI_API_KEY  = <ключ OpenRouter или совместимого OpenAI-API провайдера>
AI_BASE_URL = https://openrouter.ai/api/v1   # опционально
AI_MODEL    = anthropic/claude-haiku-4.5     # опционально
```

Без переменных проект остаётся полностью статическим и работает где угодно.

## AI-инструменты и проверка

- **Инструменты**: Claude Code в агентном режиме. Работа шла по конвейеру:
  сначала детальное ТЗ (сценарий, формулы модели с коэффициентами,
  дизайн-система, критерии приёмки), затем фазы каркас → модель → UI →
  полировка с самопроверкой по чеклисту после каждой фазы. AI использовался
  на всех этапах, включая проработку ТЗ, — качество постановки задачи
  определяет качество результата.
- **Что делал сам**: выбор сценария и механики (диапазон + уверенность вместо
  «точного» числа), архитектурные развилки (вся математика — чистые функции в
  `src/model/`, без chart-библиотек и UI-китов), приёмка и правки после
  самостоятельного прогона (кнопка случайного сигнала, фикс host у dev-сервера).
- **Как проверял**: юнит-тесты модели (vitest, 13 кейсов), ручной прогон каждого
  контрола в браузере, крайние случаи (ноль событий, все сигналы выключены,
  экстремумы слайдеров, 20+ событий — без NaN), сверка панели «Как посчитано»
  с кодом `engine.ts`, мобильная ширина 375px, чистая консоль и `npm run build`.

Подробный журнал чекпоинтов — в приложении: меню «AI Worklog»
(данные в `src/worklog/worklog.ts`).
